Mappin'

（マッピン）— 登山準備の早送りマップ

お題「▶︎▶︎」の解釈

▶︎▶︎ ＝ 連なる「山々」 ＋ 時間を短縮し効率を高める「早送り（タイパ）」

このシンボルから2つの意味を見出し、「登山者の事前準備をいかに効率化できるか」という問いからプロジェクトをスタートしました。

目指したのは、便利ツールの先

このサービスが広く普及・加速することで、深刻化する山岳遭難を防ぎ、行政や救助にかかるコストを削減する。さらには、地方の登山道管理やインフラ維持を持続可能にする——そんな社会課題の解決に直結する仕組みを模索しました。

Mappin'（マッピン）

その答えが、マッピング技術を活用した情報収集・提供プラットフォーム「Mappin'」。開発環境には Leaflet＋国土地理院地図（GitHub Pages）、Cloudflare Workers＋KV、AI（Claude）＋OpenStreetMap を採用しました。

最も工夫したのは「情報の鮮度をピンに持たせない」設計——ピンは位置と入口だけを持ち、ワンタップで常に最新の公式ページへ直行。そして登山道をタップすると、自分のルートに関係する情報だけが浮かび上がります。

作品URL — いま皆さんのスマホで開けます

https://fumi-june.github.io/ai-hackathon-2026/hikemap/

  • 公式の危険情報 59ピン（3都県横断）・ワンタップで公式ページ直行
  • 登山道24本 — 自分のルートをタップすると沿線500mの情報だけ浮かぶ
  • その場で誰でも投稿（写真つき）— 双方向の目撃網

▶ ライブデモ：ピン→公式直行 ／ 大倉尾根タップ→沿線集計 ／ 会場から投稿

最大の強み：情報が一方通行ではない

行政が発信した公式情報だけでなく、実際に現地を歩く利用者のリアルな投稿（写真つき）もその場で集まります。行政側もこの最新データを参照することで、危険箇所の事前対応や的確な安全対策を講じられる「双方向のフィードバック機構」。

つまり、利用者が増えれば増えるほど情報の濃度と精度が上がり、登山者と行政の双方にとって価値が高まり続ける仕組みです。

開発に使用したツール類

  • Claude Code — 設計・実装・デプロイ・データ構築（公式発表＋OSMからピン59・ルート24本をAIが抽出・検証）
  • Leaflet ＋ 国土地理院地図 — 地図表示（GitHub Pages配信）
  • Cloudflare Workers ＋ KV — 投稿・写真の共有バックエンド
  • OpenStreetMap / Overpass API — 登山道・山小屋・トイレの線形と位置
  • Google Chat — URL・コメントを共有／Let's note から EVO-X2 を遠隔操作

※ 今回は海外と日本で連携して開発したため、機材構成は遠隔でのやり取りを想定したものになっている
